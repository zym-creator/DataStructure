# 00 C++ 内存、深拷贝与资源管理

手写数据结构绕不开动态内存。本章应在动态数组和链表之前学习。

## 1. 对象存在哪里

- 自动存储期对象通常随作用域结束自动销毁：`int x; std::vector<int> v;`。
- `new T` 在自由存储区创建对象，必须由对应的 `delete` 释放。
- `new T[n]` 必须由 `delete[]` 释放，二者不能混用。
- 指针只保存地址，不拥有它指向的数据这一事实；“谁负责释放”必须由设计明确。

```cpp
int* p = new int[10];
delete[] p;
p = nullptr; // 避免继续误用旧地址
```

**[注意]** 内存泄漏是忘记释放；悬空指针是对象已销毁但地址仍被使用；重复释放是同一地址被 `delete` 两次。三者都不能靠“程序暂时没崩”判断正确。

## 2. 浅拷贝为什么危险

编译器生成的默认复制会逐成员复制。若成员是 `int* data_`，复制的只是地址：

```text
a.data_ ----> [1, 2, 3]
b.data_ -----^
```

`a` 和 `b` 指向同一数组。修改一个会影响另一个；析构时还会对同一地址释放两次。这叫**浅拷贝**。

## 3. 深拷贝

深拷贝为新对象分配独立空间并复制元素：

```text
a.data_ ----> [1, 2, 3]
b.data_ ----> [1, 2, 3]
```

需要实现复制构造函数和复制赋值运算符。赋值还要正确处理 `a = a`，并保证分配失败时原对象不被破坏。常用做法是 copy-and-swap：参数先复制成功，再交换资源。

## 4. Rule of Three / Five / Zero

- **Rule of Three**：若类需要自定义析构、复制构造、复制赋值中的一个，通常三个都需要。
- **Rule of Five**：C++11 后还应考虑移动构造和移动赋值。
- **Rule of Zero**：优先把资源交给 `std::vector`、`std::unique_ptr` 等 RAII 类型，让类无需手写这五个函数。

移动不是复制数据，而是转移资源所有权。被移动对象仍必须“有效但状态未指定”，至少可以安全析构和重新赋值。

## 5. RAII

RAII 的含义是“资源获取即初始化”：资源的生命周期绑定到对象生命周期。构造成功即持有资源，析构自动释放，因此异常和提前 `return` 也不会泄漏。

```cpp
auto p = std::make_unique<int[]>(10); // 自动 delete[]
std::vector<int> values(10);          // 更常用
```

**[工程实践]** 裸指针可以表示“不拥有的观察关系”；拥有资源时优先 `std::unique_ptr`。共享所有权确实存在时才用 `std::shared_ptr`，不要用它掩盖生命周期设计不清。

## 6. 异常安全

- 基本保证：异常后对象仍有效且不泄漏。
- 强保证：异常后状态与调用前相同。
- 不抛异常保证：操作承诺不会抛出，移动操作常标记 `noexcept`。

动态数组扩容应先成功分配和复制新空间，最后再释放旧空间。顺序反过来会在分配失败时丢失原数据。

## 7. 自查清单

- 每个 `new` 是否有唯一、匹配的释放责任？
- 类能否复制？若能，是深拷贝；若不能，是否显式 `= delete`？
- 自赋值是否安全？移动后是否可析构？
- 空对象、零容量和分配失败是否有合理行为？
- 是否可以用标准库类型实现 Rule of Zero？
