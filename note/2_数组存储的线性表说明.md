# 2. 数组存储的线性表

> 对应源码：`code/2_线性结构.cpp`

## 1. 什么是线性表

线性表是一组有顺序的数据。

- 除第一个元素外，每个元素都有一个直接前驱。
- 除最后一个元素外，每个元素都有一个直接后继。

```text
下标：  0    1    2    3
数据： 11   77   25   33
```

数组存储又叫顺序存储。元素在内存中连续排列，因此可以通过下标直接找到元素。

## 2. 数据结构

```cpp
static constexpr int MaxSize = 100;

ElementType data_[MaxSize]{};
int length_ = 0;
```

| 成员 | 作用 |
| --- | --- |
| `MaxSize` | 数组最多容纳 `100` 个元素，程序运行期间不能改变 |
| `data_` | 内置数组，真正保存元素，没有使用 `std::array` |
| `length_` | 当前已经存放的元素数量 |

`MaxSize` 是容量，`length_` 是当前长度。刚创建线性表时，容量是 `100`，长度是 `0`。

## 3. 基本性质

- 元素在内存中连续存放。
- 通过下标访问元素的复杂度为 `O(1)`。
- 容量固定，当 `length_ == MaxSize` 时不能继续插入。
- 在中间插入或删除时，需要移动其他元素。
- 不需要使用 `new` 和 `delete`。

## 4. 主要操作

### `Find`：按值查找

从下标 `0` 开始逐个比较。找到时返回下标，没找到时返回 `-1`。

```cpp
for (int i = 0; i < length_; ++i) {
    if (data_[i] == value) {
        return i;
    }
}
return -1;
```

### `Insert`：插入

1. 检查线性表是否已满。
2. 检查 `index` 是否在 `0` 到 `length_` 之间。
3. 从最后一个元素开始向后移动，为新元素留出位置。
4. 将新元素写入 `data_[index]`。
5. 将 `length_` 加一。

```cpp
for (int i = length_; i > index; --i) {
    data_[i] = data_[i - 1];
}

data_[index] = value;
++length_;
```

插入时必须从后向前移动。如果从前向后移动，前一个元素会覆盖后一个元素，导致原数据丢失。

### `Delete`：删除

删除元素后，将它后面的元素依次向前移动，最后将 `length_` 减一。

```cpp
for (int i = index; i < length_ - 1; ++i) {
    data_[i] = data_[i + 1];
}

--length_;
```

### `FindKth`：按下标查找

检查下标合法后，直接读取 `data_[index]`，并通过引用参数 `value` 把结果传回调用处。

### `Length`：获取长度

直接返回 `length_`，复杂度为 `O(1)`。

### `Print`：输出元素

从下标 `0` 遍历到 `length_ - 1`，依次输出所有元素。

## 5. 复杂度

| 操作 | 最好情况 | 最坏情况 | 原因 |
| --- | --- | --- | --- |
| 按下标访问 | `O(1)` | `O(1)` | 可直接计算元素地址 |
| 按值查找 | `O(1)` | `O(n)` | 可能需要遍历全部元素 |
| 插入 | `O(1)` | `O(n)` | 尾部无需移动，头部需要全部移动 |
| 删除 | `O(1)` | `O(n)` | 尾部无需移动，头部需要全部移动 |

## 6. 优缺点

### 优点

- 结构简单，容易理解和调试。
- 按下标访问非常快。
- 无需手动管理节点内存。

### 缺点

- 最大容量需要提前确定。
- 中间插入和删除需要移动元素。
- 如果预留容量过大，可能浪费空间。

## 7. 适用场景

数组线性表适用于：

- 元素数量上限明确。
- 经常按下标读取元素。
- 插入和删除操作较少。

## 8. 常见错误

- 把 `index == length_` 当成删除的合法下标。它只在尾部插入时合法。
- 插入时从前向后移动，造成数据被覆盖。
- 忘记修改 `length_`，导致后续操作使用错误长度。
- 当 `length_ == MaxSize` 时仍然插入，造成数组越界。
