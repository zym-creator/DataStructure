# 22. Kruskal 算法

> 对应源码：`code/22_Kruskal.cpp`

## 1. 按边构建最小生成树

Kruskal 与 Prim 的目标相同，都是寻找连通无向带权图的最小生成树。

Prim 始终维护一棵连通的树，Kruskal 则从多个独立顶点开始，逐渐将它们合并成一棵树。

## 2. 边集存储

Kruskal 需要按权重考察整张图的边，因此直接保存边数组：

```cpp
struct Edge {
    Vertex first;
    Vertex second;
    WeightType weight;
};

std::vector<Edge> edges_;
```

开始时使用 `std::sort` 按权重从小到大排序。

## 3. 贪心步骤

1. 将所有顶点看作独立集合。
2. 将所有边按权重从小到大排序。
3. 依次考察每条边 `(u,v)`。
4. 如果 `u` 和 `v` 属于不同集合，选中该边并合并两个集合。
5. 如果它们已在同一集合，加入该边会形成环，因此跳过。
6. 选中 `V-1` 条边时完成。

## 4. 并查集检测环

源码复用第 15 章的思想，根节点保存集合大小的负数：

```cpp
std::vector<int> parents_;
```

`Find` 使用路径压缩，`Union` 使用按大小合并。对一条边：

```cpp
if (sets.Union(edge.first, edge.second)) {
    result.edges.push_back(edge);
    result.totalWeight += edge.weight;
}
```

`Union` 返回 `false` 表示两个顶点已经连通，这条边会形成环。

## 5. 为什么贪心选择正确

当一条边连接两个不同连通分量时，它跨越了当前森林的一个切分。Kruskal 选择能够连接不同分量的最小权边。根据切分性质，它可以安全存在于某棵 MST 中。

不断重复这个选择，就能得到全局最小的生成树。

## 6. 不连通图

如果所有边都考察完后，选中边数仍小于 `V-1`，图不连通，不存在覆盖所有顶点的生成树。

此时已选中的边实际上组成了最小生成森林，但示例接口会通过 `connected=false` 报告 MST 不存在。

## 7. 负权边

Kruskal 允许负权边。负权边会在排序后优先被考察，只要不形成环就可以加入 MST。这与 Dijkstra 不允许负权边不同。

## 8. 复杂度

| 阶段 | 复杂度 |
| --- | --- |
| 边排序 | `O(E log E)` |
| 并查集操作 | 总计约 `O(E α(V))` |
| 总时间 | `O(E log E)` |
| 辅助空间 | `O(V+E)` |

排序是 Kruskal 的主要时间开销。

## 9. Prim 和 Kruskal 对比

| 特点 | Prim | Kruskal |
| --- | --- | --- |
| 选择对象 | 从当前树向外的最小边 | 全图尚未形成环的最小边 |
| 中间状态 | 始终是一棵连通树 | 是多棵树组成的森林 |
| 核心辅助结构 | 最小堆 | 排序 + 并查集 |
| 常见适用图 | 稠密图或邻接结构明确 | 稀疏图或边集输入 |

## 10. 与原实现的区别

重构版取消未使用的邻接矩阵和全局状态，使用 `std::sort` 直接排序边，并将并查集封装为类。输出时只遍历实际选中的边，避免原代码按 `Nv` 访问仅有 `Nv-1` 条边的数组而越界。
