# 3. 链表存储的线性表

> 对应源码：`code/3_链表存储的线性表.cpp`

## 1. 什么是单链表

单链表也是线性表，但元素不需要在内存中连续排列。每个节点除了保存数据，还保存下一个节点的地址。

```text
head_ -> [11 | next] -> [77 | next] -> [25 | next] -> [33 | nullptr]
```

每个节点只知道下一个节点，不知道上一个节点，所以称为单链表。

## 2. 节点和头指针

```cpp
struct Node {
    ElementType data;
    Node* next;
};

Node* head_ = nullptr;
int length_ = 0;
```

| 成员 | 作用 |
| --- | --- |
| `data` | 保存当前节点的元素值 |
| `next` | 保存下一个节点的地址，最后一个节点中为 `nullptr` |
| `head_` | 保存第一个节点的地址，空链表中为 `nullptr` |
| `length_` | 记录当前节点数量 |

## 3. 基础指针语句

| 代码 | 含义 |
| --- | --- |
| `Node* p` | `p` 是一个指向 `Node` 的指针 |
| `nullptr` | 指针没有指向任何节点 |
| `p->data` | 访问 `p` 所指节点的 `data` |
| `p->next` | 访问 `p` 所指节点的 `next` |
| `new Node{...}` | 申请内存并创建新节点 |
| `delete p` | 释放 `p` 所指节点的内存 |

不能通过 `nullptr` 访问 `data` 或 `next`。通过 `new` 创建的节点，不再使用时必须用 `delete` 释放。

## 4. 基本性质

- 节点在内存中可以不连续。
- 链表没有固定的 `MaxSize`，需要时可以申请新节点，但仍受可用内存限制。
- 不能直接跳到第 `index` 个节点，必须从 `head_` 开始顺着 `next` 走。
- 已经找到位置后，插入和删除只需要修改指针，不需要移动其他元素。
- 每个节点除了保存数据，还需要额外保存一个 `next` 指针。

## 5. 主要操作

### `GetNode`：按下标找节点

从 `head_` 开始，每次执行：

```cpp
current = current->next;
```

直到走到指定下标。

代码中有两个 `GetNode`：

```cpp
Node* GetNode(int index);
const Node* GetNode(int index) const;
```

- 第一个返回可修改节点的指针。
- 第二个返回只读节点的指针。
- 这种同名但版本不同的函数叫作函数重载。

### `Find`：按值查找

从 `head_` 开始遍历，比较 `current->data` 与目标值。找到时返回下标，没找到时返回 `-1`。

### `Insert`：插入

在头部插入时，新节点的 `next` 指向原来的 `head_`，再让 `head_` 指向新节点：

```cpp
head_ = new Node{value, head_};
```

在其他位置插入时，先找到前一个节点 `previous`，再把新节点接入链中：

```cpp
Node* previous = GetNode(index - 1);
previous->next = new Node{value, previous->next};
```

### `Delete`：删除

1. 保存待删除节点的地址。
2. 修改 `head_` 或 `previous->next`，让链表跳过该节点。
3. 使用 `delete` 释放该节点。
4. 将 `length_` 减一。

删除头节点：

```cpp
nodeToDelete = head_;
head_ = head_->next;
delete nodeToDelete;
```

删除其他节点：

```cpp
Node* previous = GetNode(index - 1);
nodeToDelete = previous->next;
previous->next = nodeToDelete->next;
delete nodeToDelete;
```

### `Clear`：释放所有节点

```cpp
while (head_ != nullptr) {
    Node* nodeToDelete = head_;
    head_ = head_->next;
    delete nodeToDelete;
}
```

必须先让 `head_` 移到下一个节点，再释放原头节点。否则后续节点的地址会丢失。

## 6. 析构函数

```cpp
~LinkedList() {
    Clear();
}
```

当 `LinkedList` 对象离开作用域时，析构函数自动运行。它调用 `Clear` 释放所有节点，避免内存泄漏。

当前版本禁止默认拷贝：

```cpp
LinkedList(const LinkedList&) = delete;
LinkedList& operator=(const LinkedList&) = delete;
```

因为直接拷贝 `head_` 只会复制地址，两个对象会指向同一批节点，最后可能重复执行 `delete`。

## 7. 复杂度

| 操作 | 最好情况 | 最坏情况 | 原因 |
| --- | --- | --- | --- |
| 按下标访问 | `O(1)` | `O(n)` | 下标 `0` 是头节点，其他位置需遍历 |
| 按值查找 | `O(1)` | `O(n)` | 可能需要遍历全部节点 |
| 插入 | `O(1)` | `O(n)` | 头部无需遍历，其他位置需先查找 |
| 删除 | `O(1)` | `O(n)` | 头部无需遍历，其他位置需先查找 |
| 清空 | `O(n)` | `O(n)` | 每个节点都需要释放 |

## 8. 数组与链表对比

| 性质 | 数组线性表 | 单链表 |
| --- | --- | --- |
| 内存位置 | 连续 | 不要求连续 |
| 容量 | 当前实现固定为 `100` | 可按需创建节点 |
| 按下标访问 | `O(1)` | `O(n)` |
| 头部插入或删除 | `O(n)` | `O(1)` |
| 额外存储 | 不需要 `next` | 每个节点需要 `next` |
| 实现难度 | 较低 | 较高，需处理指针和内存 |

## 9. 常见错误

- 直接移动 `head_` 遍历链表，导致头节点地址丢失。遍历时应使用临时指针 `current`。
- 删除节点后继续访问该指针。
- 通过 `new` 创建节点后忘记 `delete`，造成内存泄漏。
- 没有单独处理 `index == 0`，但头节点没有前一个节点。
- 没检查 `nullptr` 就访问 `current->data` 或 `current->next`。
