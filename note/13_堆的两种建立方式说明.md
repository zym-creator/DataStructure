# 13. 堆的两种建立方式

> 对应源码：`code/13_堆的两种建立方式.cpp`

## 1. 建堆的目标

源码建立的是最小堆：它是一棵完全二叉树，每个父节点都不大于它的孩子。因此，数组第一个元素始终是最小值。

数组从下标 `0` 开始，节点的关系为：

```text
父节点：(i - 1) / 2
左孩子：2 * i + 1
右孩子：2 * i + 2
```

一组相同的数据可以建成多种形态不同的最小堆。只要满足父节点不大于孩子，它们都是正确的堆。

## 2. 方式一：逐个插入

第一种方式从空堆开始，对每个输入值调用 `Insert`：

1. 将新元素放在数组末尾，保持完全二叉树的形状。
2. 将新元素与父节点比较。
3. 如果新元素更小，交换两者并继续向上。

例如依次插入 `30、10、20`：

```text
插入 30：       插入 10 并上滤：    插入 20：

   30                 10                 10
                     /                  /  \
                    30                 30   20
```

每次插入最多上滤一棵树的高度，一次为 `O(log n)`；插入 `n` 个元素的总时间复杂度是 `O(n log n)`。

## 3. 方式二：自底向上调整

第二种方式先把所有元素按输入顺序放入数组。此时已经得到完全二叉树的形状，但还不一定满足最小堆的大小关系。

下标范围为 `[size / 2, size - 1]` 的节点都是叶子。单个叶子没有孩子，天然满足堆的条件，所以不需要调整。

最后一个非叶节点的下标是：

```cpp
size_ / 2 - 1
```

从这个节点向前遍历到根，对每个节点进行下滤：

```cpp
for (int i = size_ / 2 - 1; i >= 0; --i) {
    SiftDown(i);
}
```

下滤时，将当前节点与两个孩子中较小的一个比较。如果孩子更小，就交换并继续向下。

## 4. 为什么自底向上是 `O(n)`

表面上，每个下滤最坏需要 `O(log n)`，但大部分节点都靠近叶子，它们最多只能下滤一两层：

- 约 `n / 2` 个叶子不需要下滤。
- 约 `n / 4` 个节点最多下滤 `1` 层。
- 约 `n / 8` 个节点最多下滤 `2` 层。
- 只有根节点可能下滤 `log n` 层。

把所有节点的实际调整量相加，结果与 `n` 成正比，所以总时间复杂度是 `O(n)`。

## 5. 两种方式对比

| 建堆方式 | 过程 | 时间复杂度 | 适用情况 |
| --- | --- | --- | --- |
| 逐个插入 | 从空堆开始，每次上滤 | `O(n log n)` | 数据逐个到来 |
| 自底向上 | 先形成数组，再从非叶节点下滤 | `O(n)` | 所有数据已经存在 |

两种方式都需要 `O(n)` 的数组存储空间。对同一组输入，它们的层序遍历结果可能不同，但都应当满足最小堆性质。

## 6. C++ 内存管理

`MinHeap` 在构造时使用 `new[]` 申请数组，在析构时使用 `delete[]` 释放。它禁用了默认拷贝，避免两个堆指向同一块动态数组并重复释放。

整个实现只使用 `<iostream>`，数组存储、交换、上滤和下滤都手动实现，便于观察建堆的完整过程。
