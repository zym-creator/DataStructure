# 15. 并查集的表示

> 对应源码：`code/15_并查集的表示.cpp`

## 1. 并查集解决什么问题

并查集（Disjoint Set Union，DSU）用于管理若干个互不相交的集合，核心操作是：

- `Find`：查找元素所属集合的代表元素。
- `Union`：合并两个元素所在的集合。
- `IsConnected`：判断两个元素是否属于同一集合。

它常用于判断网络连通性、检测无向图中的环，以及 Kruskal 最小生成树算法。

## 2. 用森林表示集合

每个集合用一棵树表示，整个并查集是由多棵树组成的森林。树的根节点是该集合的代表元素。

不需要为节点建立孩子链表，只要保存每个节点的父节点即可。源码使用动态数组：

```cpp
int* parents_;
```

元素的值为 `1 ~ n`，它在数组中的下标为 `element - 1`。

## 3. 负数根节点表示法

`parents_` 同时保存父节点和集合大小：

```text
parents_[i] < 0：i 是根，-parents_[i] 是集合大小
parents_[i] >= 0：parents_[i] 是 i 的父节点下标
```

初始时每个元素各自组成一个集合：

```text
元素：1   2   3   4   5
数组：-1 -1  -1  -1  -1
```

所有节点都是根，每个集合的大小都是 `1`。

假设合并后得到：

```text
元素：1   2   3  4
下标：0   1   2  3
数组：-4  0   0  2
```

这里数组中非负数表示的是父节点的数组下标。例如元素 `4` 的下标是 `3`，`parents_[3] = 2` 表示它的父节点是下标 `2` 对应的元素 `3`。对应关系为：

```text
2 -> 1
3 -> 1
4 -> 3 -> 1
```

根 `1` 保存 `-4`，表示该集合有 `4` 个元素。

## 4. Find 与路径压缩

查找时沿父节点不断向上，遇到负数就找到了根：

```cpp
int FindRootIndex(int index) {
    if (parents_[index] < 0) {
        return index;
    }

    parents_[index] = FindRootIndex(parents_[index]);
    return parents_[index];
}
```

关键语句是：

```cpp
parents_[index] = FindRootIndex(parents_[index]);
```

它不仅找到根，还会让当前节点直接指向根，这就是路径压缩。

```text
压缩前：4 -> 3 -> 2 -> 1
压缩后：4 -> 1，3 -> 1，2 -> 1
```

第一次查找在修改树结构，后续查找就能更快到达根。

## 5. Union 与按大小合并

合并时先找到两个根。如果根相同，两个元素已经在同一集合中。

如果根不同，将较小的树连到较大的树下面：

```cpp
if (parents_[firstRoot] > parents_[secondRoot]) {
    // 交换两个根，使 firstRoot 代表较大集合。
}

parents_[firstRoot] += parents_[secondRoot];
parents_[secondRoot] = firstRoot;
```

由于根保存的是负数：

```text
-5 表示 5 个元素
-2 表示 2 个元素
```

`-5 < -2`，因此值更小的根反而代表更大的集合。

按大小合并可以避免小树反复成为大树的父树，从而控制树高。

## 6. 示例的合并过程

初始有 `8` 个集合。执行：

```cpp
sets.Union(3, 5);  // {3, 5}
sets.Union(1, 3);  // {1, 3, 5}
sets.Union(2, 4);  // {2, 4}
sets.Union(8, 6);  // {6, 8}
```

此时的集合是：

```text
{1, 3, 5}  {2, 4}  {6, 8}  {7}
```

再执行：

```cpp
sets.Union(4, 5);
```

`4` 所在的大小为 `2` 的集合会连到 `5` 所在的大小为 `3` 的集合下，得到：

```text
{1, 2, 3, 4, 5}  {6, 8}  {7}
```

因此当前集合数量为 `3`。

## 7. 复杂度

若不进行优化，树可能退化成链表，`Find` 最坏为 `O(n)`。

同时使用按大小合并和路径压缩后，单次操作的均摊时间复杂度为：

```text
O(α(n))
```

`α(n)` 是反阿克曼函数，增长极其缓慢。对于实际可处理的数据量，它可以近似理解为常数，因此并查集的操作通常被认为接近 `O(1)`。

存储 `n` 个元素的父节点数组需要 `O(n)` 空间。

## 8. 与原实现的区别

原代码的 `Find` 需要先遍历固定长度 `1000` 的数组，根据 `Data` 寻找下标，然后再向上查找根。重构后将元素 `1 ~ n` 直接映射到下标 `0 ~ n - 1`，取消线性扫描。

同时，重构版：

- 根据实际元素数量使用 `new[]` 分配数组。
- 检查元素是否在有效范围内，避免越界。
- 通过负数根节点保存集合大小。
- 使用路径压缩和按大小合并提高查找效率。
- 用构造和析构函数管理动态内存。
